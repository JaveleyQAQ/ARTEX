# 反馈驱动的自主规划

## 设计目标

Planner 不应只读取 Worker 的一句完成摘要，然后继续派发相似任务。每条探索 Intent 都应形成可追溯的闭环：提出假设、执行观察、记录证据、复盘结果，并让后续规划读取复盘结论。

## 复盘结果

Planner 对终态 Intent 使用以下四种结果：

| Outcome | 含义 | 规划动作 |
| --- | --- | --- |
| `supported` | 可复核观察满足原验收标准 | 保留支持证据，评估下游假设 |
| `refuted` | 有效观察直接反证原假设 | 更新知识边界，避免无新证据重复同一路线 |
| `inconclusive` | 观察不完整或证据不足 | 明确缺失证据，设计最小补证动作 |
| `execution_failed` | 工具、网络、模型或权限故障导致没有有效观察 | 先定位故障；只有执行条件或策略改变后才重试 |

工具超时、权限拒绝或执行异常不是反证；Worker 正常结束也不自动证明假设成立。Finding 仍必须经过独立证据复核及人工 triage 流程。

## 持久化

Planner 通过 `record_intent_review` 工具记录复盘：

- 仅允许复盘当前任务中已进入 done、blocked、exhausted 或 stopped 的 Intent。
- outcome 必须属于上述四种枚举，reason 必须非空。
- evidence_ids 仅允许引用当前任务中的 fact/finding 节点。
- 每条 Intent 只接受首次复盘，避免后续轮次无意覆盖历史结论。
- 复盘保存在现有 `exploration_nodes.payload` JSONB 的 `planner_review` 字段中，无需新增表或迁移。
- Graph Overview 在 `recent_done_intents` 中返回复盘结论，并提供 `intent_review_stats` 计数。

复盘记录包含 outcome、reason、evidence_ids 和 reviewed_at。证据原文仍保存在原始事实/漏洞节点中，复盘只保存引用，不复制证据内容。

## 安全与边界

- 复盘工具只写入本任务的探索图，不执行目标访问、扫描、探测或利用。
- 证据引用在工具层和数据库层双重校验，避免跨任务或错误类型节点被引用。
- 复盘不会直接把候选 Finding 提升为已确认漏洞，也不会改变独立 Verifier 的职责。
- 不引入语义模糊去重；复盘结论只作为后续 Planner 的决策上下文。

## 后续演进

1. 汇总假设支持率、执行失败率、重复意图率和复盘覆盖率。
2. 在明确来源、适用条件、证据质量和过期策略后，将人工确认的复盘沉淀为可检索经验。
3. 再引入动态优先级建议和跨 Agent 经验共享；优先级不得覆盖 Scope、Guard、审批和网络出口策略。
